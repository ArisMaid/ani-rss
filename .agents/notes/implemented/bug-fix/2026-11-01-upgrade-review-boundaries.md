# Agent Note: 洗版的作品身份、传输归属与恢复边界

Status: implemented

## Problem

混合 RSS 的集号可以命中其他作品的旧媒体。清理旧版时，曾经借用的普通做种任务也可能被移除。备份切换期间已经开始的洗版扫描仍持有旧状态。普通订阅和索引还会把预览、历史快照或已结束任务当作本轮工作。

## Decision

蜜柑详情提供唯一 Bangumi 作品 ID 和该作品的 RSS 时，专属源继承作品身份。自定义或混合源逐条核对已登记的作品名与别名，提交时再核对下载的视频文件名。历史候选和旧的待安装清单经过同一检查。普通订阅在各来源分别映射集号，再跨源比较；只有日常扫描写入候选与游标。

洗版交接要求媒体库仍在配置中。已进入安装的提交继续按清单恢复。清理暂存源前联合核对安装清单、原下载器与作业归属、保存根以及其他活动引用。恢复数据库须等待在途调度与洗版 API 请求退出，切库后从恢复的作业重建预约。下载器清单读取失败时保留预约和任务 ID，读到完整清单并核实任务消失后才释放并重提。

Emby 分页写入临时批次，验证唯一条目数后才发布。空增量沿用已完成快照，有变更时只合并变更项；重复分页丢弃未完成批次重读。调度直接按 SQLite 状态和重试时间取到期任务。每一对候选与已有版本按实际交集章节比较，复用比较结果。季度显示名与扫描范围分别处理。[季度选择](../feature/2026-10-31-campaign-title-exclusions.md)

## Alternatives considered

按路径或 hash 查找任务能兼容缺少来源的历史版本，但同一资源可以属于普通订阅、其他实例或其他作品，因此不足以授权停止或删除。保留静态路径检查作为文件清单验证。

## Consequences

无法证明独占的做种任务和暂存源继续保留。混合源文件只有集号、无法识别作品时等待核对。普通质量订阅有容器白名单时，读取实际种子文件清单；qBittorrent 磁力停在元数据阶段，核对后开始。其他下载器只有磁力且无法预检时暂缓。关闭重命名的 qBittorrent 合集也须先选择文件。

## Testing

隔离复验使用本地 HTTP、SQLite、真实备份恢复和 ffmpeg 生成的三段视频。错误发布及错误文件名分别被拒，旧视频哈希一致，正确 1080p 视频安装成功。两次替换后普通做种任务删除调用为零。空增量三次后的索引仍为两行，1,000 条历史完成作业的空闲调度只执行一次待办查询。Vue 组件和真实 Chrome 均验证乱序返回：B 的三项明细先到，A 的三项随后到达，保护开关的唯一写请求指向 B。Maven verify 发现 530 项测试，520 项通过、10 项跳过；SpotBugs 及 JaCoCo 门槛通过。前端 52 项测试通过。真实下载器、Emby 和用户媒体库仍需部署环境验收。
