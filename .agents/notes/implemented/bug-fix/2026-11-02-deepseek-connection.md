# Agent Note: 洗版辅助的模型发现与连接自检

Status: implemented

## Problem

首次配置时，用户输入密钥后立即获取模型，服务却读取尚为空的已保存设置。连接自检也忽略当前表单，并会用配置快照整份回写。切换服务地址时，留空的密钥可能被发送到新地址。

## Decision

模型发现与 JSON 自检只接收本次表单的连接字段。服务端仅在相同 API 地址复用已保存密钥。手工输入模型与拉取列表都可进入自检。通过自检的草稿在保存前不影响正在运行的辅助分析，保存时只接受服务端验证过的地址、密钥和模型组合。自检仍计入服务端预算。保留已保存配置的原有 API 用法。

官方服务的自检和后台证据提取使用一致的非思考 JSON 请求。候选分析按实际返回的候选逐条缓存，缺失或畸形的条目留待补证，去除与逐条记录重复的整批缓存。

## Alternatives considered

先保存再获取模型可以复用旧接口，但会让用户必须先修改正在使用的连接才能试用新模型。每次保存启用时直接重新请求模型实现简单，却使已经通过自检的同一连接重复消耗调用。复用已有的限时缓存，仅保存已验证组合的摘要。

## Consequences

首次配置不需要额外保存或重复付费自检。已保存的连接跨重启保留验证状态。草稿的验证凭据只有服务端摘要，有效期 30 分钟，服务重启或缓存被逐出后需要再自检一次。兼容服务即使没有模型列表也可以直接输入 ID。模型列表与自检的旧响应会在表单修改后失效。模型明确返回整批无证据时仍可缓存，旧版未记录对应候选 ID 的空缓存会重新核对一次。

## Testing

2026-11-02 使用隔离实例，经应用的 HTTP 接口连接官方服务，列出 `deepseek-flash` 和 `deepseek-v4-pro`。其中 `deepseek-flash` 通过一次结构化自检，消耗 57 token。实连前后配置版本相同，关停后检查配置、SQLite 与日志等 7 个文件，未检出测试密钥。

真实 Chrome 使用回环服务验证首次配置、上游 401 后保持登录、列表选择、手输模型、缺少列表接口、保存刷新、跨地址不复用密钥及明确清除。隔离实例验证重启后仍可使用已验证连接、预算耗尽时未发出请求。组件测试覆盖重复点击和乱序响应。候选分析测试验证漏项可重试、已返回的条目不再收费。真实媒体候选的判断质量仍需人工标注样本验收。

前端 53 项测试和生产构建体积门槛通过。后端全量测试 523 项通过、10 项跳过。静态检查发现可空的请求响应临时变量后，改为请求成功直接返回。最终重新运行 18 项相关测试，SpotBugs 零告警，JaCoCo 达标。最终 JAR 的页面入口和洗版页面脚本与实测前端构建逐字节一致。
