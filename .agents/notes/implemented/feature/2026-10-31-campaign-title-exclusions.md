# Agent Note: 季度订阅支持逐部取消

Status: implemented

## Problem

季度目录只读，用户无法在创建或编辑订阅时取消指定作品。仅在前端隐藏条目会被后台 Mikan 扫描及 Bangumi 补全重新加入。

## Decision

目录默认全部订阅，每行可取消；取消时通过服务端将 Mikan ID 解析为 Bangumi 作品 ID，再把映射存入本季度 Campaign 的 excludedMikanSubjects。取消解析失败时显示错误并保留原选择，解析中禁止保存。重新勾选删除映射，刷新同季度保留取消项，切换季度重置此季度选择。

后台 Mikan 跳过取消条目，Bangumi 补全与生效任务选择均按作品 ID 排除；其他订阅仍可独立订阅同一作品。取消不删除作品档案、下载内容或媒体。保存通过同一数据库事务写入季度选择和相关作品修订号，并与现有安装锁协调，使尚未开始安装的旧决定重新校验；已经开始的安装恢复继续完成。

## Alternatives considered

在保存时统一解析所有取消作品可减少前端状态，但大量条目会拖长整个保存请求，且来源错误会阻止其他字段保存，因此改为逐次取消时解析。全局 Target.excluded 已有实现且简单，但会同时影响其他季度任务，因此不用于本季度选择。

## Consequences

收益是选择结果与实际后台行为一致。现有规则、媒体和作品档案保留；用户应用预设或保存季度选择后生效。首次取消需核对来源身份，失败保留原选择并支持重试；同季度刷新保留选择，切换季度重置草稿。

## Testing

后端针对性 39 项、前端 51 项通过，Maven verify（ci 配置）与静态检查通过。浏览器在隔离服务验证逐部取消、重启回填、取消后重新勾选、来源核对失败恢复以及切换季度后取消草稿。浏览器预期的未登录 401 和注入的身份缺失 502 保留在证据中。Windows 运行中的本轮测试 JAR 曾阻止重打包；停止本轮自建服务后重打包成功。未修改实际部署；改动归属版本 `v3.2.54.77`，公开交付结果以该标签的 Actions、Release 与镜像验收为准。
