# 2026 年夏季：真实批量订阅与下载复测

本轮使用真实公开 RSS 和本机独立 qBittorrent 实例，经应用正常订阅、择优、提交、重命名流程执行。不是回环种子或预先放置媒体的演示。当前结论为**部分通过、持续下载，尚未完成全量媒体验收**。真实 Emby 替换、安装新版后删除旧版仍未执行。

## 固定范围与规则

- 从当时 250 个季度关联档案中，冻结 83 个曾判断存在可升级候选的条目。83 是本轮订阅测试范围，不能代表所有季度作品均已检索完成；后台目录仍会补充。保留原始清单和全部失败条目。
- 首播日期 2026-07-01 至 2026-09-30，全部动画类型。最低 1080p、必须 CHS；排序维度为分辨率、字幕组、字幕组合，分辨率顺序为 1080、2160、720、480，硬门槛会拒绝低于 1080 的资源。
- 字幕组：桜都 → 绿茶 → 北宇治 → 悠哈璃羽 → SweetSub → LoliHouse；其他字幕组作为后备，无字幕组白名单或黑名单。
- 83 个真实订阅全部启用并绑定该质量规则。未通过 `exclude`、`notDownload` 或额外精确单集正则缩减范围。
- 下载位于独立的项目子目录，使用隔离 qBittorrent profile；普通、备用及单任务下载限速保持不限速。保留原先单集样例及其下载目录。

## 本轮发现并修复的问题

| 问题 | 修复与实机证据 | 状态 |
| --- | --- | --- |
| 旧样例订阅不可见 | 原订阅未启用，而页面默认筛选已启用；恢复并扩展为全 RSS 订阅。浏览器现可见全部 83 个订阅 | 已核验 |
| 普通订阅未应用洗版质量规则 | 订阅持久化引用质量规则，在每轮 RSS 去重前按规则选择，每集按组别名及联合字幕组比较 | 已运行批量提交 |
| 合集章节/文件处理错误 | 解析多集覆盖；合集保留逐集文件名，避免把多文件重命名成同一集后禁用其他文件 | 部分实机文件清单已核验，其余等元数据 |
| 新版合集择优引入重复提交 | 第一版 `.74-SNAPSHOT` 真实复测添加了 25 个冗余合集；已暂停诊断且保留任务、媒体和失败记录。修复为同订阅、同保存目录、相同季/章节类型、其他归属任务已完整覆盖时不再提交 | 修复后复验，失败批次仍保留 |
| 重复合集破坏原单集补全状态 | 保留已存在且仍满足普通规则的归属任务恢复状态，冗余合集标记为已覆盖 | 针对性回归通过 |
| Base32 缓存哈希与下载器不一致 | 18 个缓存磁力链接均能在下载器以十六进制哈希找到原任务；旧路径再次提交时报 `QBITTORRENT_DUPLICATE_UNVERIFIED`。统一缓存解析、提交和恢复身份 | 已修复并重新运行 |
| 重命名随任务数量显著变慢 | 原来每个任务反复反序列化全部作品档案；改为只查询当前作品，兼容旧 envelope 空字段，并复用本轮下载器快照 | 保留前后线程诊断，继续实机观察 |
| 短英文名称误识别 | 拒绝以单个英文片段证明跨作品身份；旧候选保留身份拒绝证据，不从测试清单删除 | 无关资源未按这两个订阅提交 |

原先“尚有 8 个未提交”的测量也使用了不同形式的哈希；统一 Base32/十六进制比较后，原计划 836 个均存在。它是对账错误，与后来在缓存运行链路中发现的真实重复提交错误分别保留。

## 后续仍需优化和验收

1. 把完整中文名、发布方季度别名的查询与来源交叉核对纳入程序，明确显示“subject 索引空”“别名命中”“身份不可信”，避免依赖本轮人工配置的查询规则。单词英文标题应依靠明确作品绑定或更强来源事实确认，保留安全的补证路径。
